# Gadget Hub — контракт API

Документ описывает согласованный контракт для реализации и подключения frontend к backend. Наличие ручки в документе не означает, что она уже реализована.

Backend: Kotlin + Spring Boot, `http://localhost:8080`. Frontend: Vue 3 + Vite + TypeScript, `http://localhost:5173`.

## 1. Общие правила

- Базовый путь: `/api`.
- Тела запросов и ответов — JSON, кодировка UTF-8, имена полей — `camelCase`.
- Для запросов с JSON-телом передавать `Content-Type: application/json`.
- Авторизация — cookie-сессия. Во всех запросах frontend указывает `credentials: "include"`. Пароль и токен в localStorage не сохраняются.
- Backend разрешает CORS с credentials для конкретного origin frontend: `http://localhost:5173`. Используем `localhost` для обоих приложений, без смешивания с `127.0.0.1`.
- Деньги — целые числа рублей: `2990` означает 2 990 ₽. Копейки в этом проекте не используются.
- ID товаров, ID пользователя и номера заказов — положительные целые числа.
- Даты заказов — ISO 8601 в UTC, например `2026-10-24T18:30:00Z`. Frontend форматирует дату для показа пользователю.
- Backend выполняет фильтрацию, сортировку, пагинацию, валидацию, расчёт корзины и создание заказов. Frontend отображает результаты, управляет интерфейсом и хранит состав корзины.
- Примеры товаров и цен демонстрационные. Массивы в примерах сокращены, если это явно указано.

### Формат ошибок

Для всех ошибок API используется одна структура:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Проверьте заполненные поля",
  "fieldErrors": {
    "phone": "Заполните обязательное поле"
  }
}
```

`code` — машинный код для frontend; `message` — сообщение на русском; `fieldErrors` — ошибки конкретных полей, всегда объект. При отсутствии ошибок полей возвращается `{}`.

Имена полей соответствуют запросу: `login`, `phone`, `minPrice`, `items`, `items[0].quantity` и т. д. Frontend связывает эти ключи с полями формы и отдельно показывает общее сообщение.

| HTTP | `code` | Когда используется |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Неправильные поля, параметры, JSON или типы данных |
| 400 | `PRODUCT_NOT_FOUND` | Неизвестный товар в составе корзины или заказа |
| 401 | `INVALID_CREDENTIALS` | Неправильная пара логин/пароль |
| 401 | `UNAUTHORIZED` | Нет действующей сессии на защищённой ручке |
| 404 | `PRODUCT_NOT_FOUND` | Не найден товар при запросе `/api/goods/{id}` |
| 500 | `INTERNAL_ERROR` | Внутренняя ошибка, включая ошибку сохранения заказа |

Пример отсутствия сессии — HTTP `401`:

```json
{
  "code": "UNAUTHORIZED",
  "message": "Для выполнения действия войдите в систему",
  "fieldErrors": {}
}
```

Пример внутренней ошибки — HTTP `500`:

```json
{
  "code": "INTERNAL_ERROR",
  "message": "Не удалось выполнить действие. Попробуйте позже",
  "fieldErrors": {}
}
```

Внутренние пути, содержимое файлов и stack trace клиенту не возвращаются. Ответ `204` не имеет тела: для него нельзя вызывать `response.json()`.

## 2. Общие модели

### Product — товар

Одна структура используется в каталоге, подборках главной, подробностях товара и расчёте корзины. Поля возвращаются всегда, `null` не используется.

```json
{
  "id": 1,
  "name": "Внешний аккумулятор 10000mAh, белый",
  "price": 2990,
  "imageUrl": "/images/goods/image_1.png",
  "type": "Внешние аккумуляторы",
  "color": "Белый",
  "rating": 4.8,
  "isNew": true,
  "isHit": false,
  "description": "Компактный внешний аккумулятор для зарядки гаджетов.",
  "characteristics": [
    {
      "name": "Ёмкость",
      "value": "10000 мА·ч"
    }
  ]
}
```

| Поле | Тип | Значение |
| --- | --- | --- |
| `id` | integer | Уникальный ID товара |
| `name` | string | Полное название |
| `price` | integer | Цена одной единицы в рублях, больше нуля |
| `imageUrl` | string | Путь изображения относительно origin backend |
| `type` | string | Тип товара, одновременно значение фильтра и подпись |
| `color` | string | Цвет, одновременно значение фильтра и подпись |
| `rating` | number | Рейтинг от 0 до 5 |
| `isNew` | boolean | Показывать лейбл «Новинка» |
| `isHit` | boolean | Показывать лейбл «Хит» |
| `description` | string | Описание для модального окна |
| `characteristics` | array | Пары строк `name` и `value` в порядке отображения; может быть `[]` |

Backend отдаёт изображения по указанным путям. Для `<img>` frontend собирает полный адрес: `http://localhost:8080` + `imageUrl`. Например: `http://localhost:8080/images/goods/image_1.png`.

Дата появления и показатель популярности задаются в серверном JSON и используются для сортировки. В API товара эти служебные поля не возвращаются. Рейтинг и популярность — разные величины. Товар может иметь оба лейбла, один или ни одного.

### CartItemInput — позиция корзины в запросе

```json
{
  "productId": 1,
  "quantity": 2
}
```

`productId` — существующий ID; `quantity` — положительное целое число. Один товар присутствует в массиве не более одного раза. Цену, название и сумму frontend не отправляет.

### OrderSummary — результат оформления и строка истории

```json
{
  "number": 1,
  "createdAt": "2026-10-24T18:30:00Z",
  "totalQuantity": 2,
  "totalPrice": 5980
}
```

`totalQuantity` — сумма единиц, а не число разных позиций. Два аккумулятора и одни наушники дают `3`. `totalPrice` — итог в рублях. Все поля обязательны.

## 3. Авторизация

Один заранее заданный тестовый пользователь: логин `student`, пароль `student`. Регистрации нет.

### POST /api/auth/login

Проверяет учётные данные и устанавливает cookie-сессию. Тело обязательно.

```http
POST /api/auth/login
Content-Type: application/json
```

```json
{
  "login": "student",
  "password": "student"
}
```

Успех — HTTP `200`, cookie устанавливается через `Set-Cookie`:

```json
{
  "id": 1,
  "login": "student"
}
```

Оба поля обязательны. Отсутствующие, пустые или состоящие только из пробелов значения дают `400`. Логин проверяется после удаления пробелов по краям; непустой пароль сравнивается как передан, без удаления пробелов.

Пример HTTP `400`:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Проверьте заполненные поля",
  "fieldErrors": {
    "login": "Заполните обязательное поле",
    "password": "Заполните обязательное поле"
  }
}
```

Неправильные учётные данные — HTTP `401`:

```json
{
  "code": "INVALID_CREDENTIALS",
  "message": "Такого пользователя нет, возможно неправильный логин или пароль — проверьте данные",
  "fieldErrors": {}
}
```

После успеха frontend сохраняет пользователя в состоянии приложения и переходит на главную. Cookie браузер обрабатывает сам; пароль в ответ не включается.

### GET /api/auth/me

Параметров и тела нет. Успех — HTTP `200`:

```json
{
  "id": 1,
  "login": "student"
}
```

Нет сессии — HTTP `401`, `UNAUTHORIZED`. Frontend вызывает ручку при запуске приложения. Этот ответ на публичной странице означает состояние гостя и сам по себе не требует перехода на логин.

### POST /api/auth/logout

Параметров и тела нет. Завершает сессию. Успех — HTTP `204`, без тела. Если сессии уже нет, также возвращается `204`.

Frontend очищает состояние пользователя и переходит на главную. Корзина в localStorage сохраняется; история заказов на сервере сохраняется.

## 4. Главная и товары

### GET /api/showcase

Публичная ручка. Параметров и тела нет. Возвращает все товары для двух каруселей, без пагинации.

Успех — HTTP `200`:

```json
{
  "newItems": [
    {
      "id": 1,
      "name": "Внешний аккумулятор 10000mAh, белый",
      "price": 2990,
      "imageUrl": "/images/goods/image_1.png",
      "type": "Внешние аккумуляторы",
      "color": "Белый",
      "rating": 4.8,
      "isNew": true,
      "isHit": false,
      "description": "Компактный внешний аккумулятор для зарядки гаджетов.",
      "characteristics": [
        { "name": "Ёмкость", "value": "10000 мА·ч" }
      ]
    }
  ],
  "hitItems": []
}
```

Каждый элемент — полный `Product`. В примере показана одна новинка и отсутствие хитов.

- `newItems`: товары с `isNew = true`, по дате появления от новых к старым.
- `hitItems`: товары с `isHit = true`, по популярности от большей к меньшей.
- При равенстве значений — ID по возрастанию.
- Один товар может входить в оба массива. Пустая подборка возвращается как `[]`.

### GET /api/goods/filters

Нужна сессия. Параметров и тела нет. Успех — HTTP `200`:

```json
{
  "types": ["Внешние аккумуляторы", "Наушники", "Смартфоны"],
  "colors": ["Белый", "Синий", "Черный"],
  "minPrice": 990,
  "maxPrice": 102099
}
```

`types` и `colors` содержат уникальные значения всего каталога по алфавиту. `minPrice` и `maxPrice` — минимальная и максимальная цены всего каталога. Данные не зависят от применённых пользователем фильтров. В учебном проекте каталог непустой.

Frontend использует возвращённые строки и как подписи чекбоксов, и как значения запросов. Самостоятельно вычислять варианты по текущей странице нельзя.

### GET /api/goods

Нужна сессия. Тела нет; настройки передаются query-параметрами.

| Параметр | Тип | По умолчанию | Правило |
| --- | --- | --- | --- |
| `minPrice` | integer | Без нижнего ограничения | Неотрицательная цена, включительно |
| `maxPrice` | integer | Без верхнего ограничения | Неотрицательная цена, включительно |
| `types` | Повторяющийся string | Все типы | Значения из `/api/goods/filters` |
| `colors` | Повторяющийся string | Все цвета | Значения из `/api/goods/filters` |
| `sort` | string | `newness` | `newness`, `popularity`, `price` |
| `direction` | string | `desc` | `asc` или `desc` |
| `page` | integer | `1` | Номер страницы от 1 |

Размер страницы фиксирован — 9. Параметр `size` не предусмотрен. `newness` сортирует по дате появления, `popularity` — по заданному показателю популярности, `price` — по цене. Для каждого поля `asc` означает возрастание, `desc` — убывание.

Пример: белые или синие товары ценой от 1 000 до 10 000 рублей, сначала дешёвые:

```text
GET /api/goods?minPrice=1000&maxPrice=10000&colors=Белый&colors=Синий&sort=price&direction=asc&page=1
```

В примере кириллица показана для чтения. Для фактического запроса используйте `URLSearchParams`, который выполняет URL-кодирование:

```ts
const params = new URLSearchParams({
  minPrice: "1000",
  maxPrice: "10000",
  sort: "price",
  direction: "asc",
  page: "1",
});
params.append("colors", "Белый");
params.append("colors", "Синий");
const response = await fetch(`${API_BASE}/api/goods?${params}`, {
  credentials: "include",
});
```

Успех — HTTP `200`. Пример результата с одним подходящим товаром:

```json
{
  "items": [
    {
      "id": 1,
      "name": "Внешний аккумулятор 10000mAh, белый",
      "price": 2990,
      "imageUrl": "/images/goods/image_1.png",
      "type": "Внешние аккумуляторы",
      "color": "Белый",
      "rating": 4.8,
      "isNew": true,
      "isHit": false,
      "description": "Компактный внешний аккумулятор для зарядки гаджетов.",
      "characteristics": [
        { "name": "Ёмкость", "value": "10000 мА·ч" }
      ]
    }
  ],
  "page": 1,
  "pageSize": 9,
  "totalItems": 1,
  "totalPages": 1
}
```

- `items` — только запрошенная страница, элементы формата `Product`.
- `page` — запрошенный номер; `pageSize` всегда `9`.
- `totalItems` — число товаров после фильтрации, до пагинации.
- `totalPages` — число страниц после фильтрации.
- Порядок обработки: фильтры → сортировка → пагинация. При равенстве значения сортировки — ID по возрастанию.
- Внутри группы типов или цветов применяется «или», между группами и ценой — «и».
- Отсутствие значений группы означает «все». Frontend при пустом выборе не отправляет параметр. Пустые значения `types=` и `colors=` игнорируются; если других значений нет, ограничение не применяется.
- Если frontend выбрал все варианты, можно передать их все или не передавать группу: результат одинаковый.
- Смена фильтров или сортировки на frontend сбрасывает страницу на `1`. Фильтры применяются по кнопке «Показать».

Если ничего не найдено:

```json
{
  "items": [],
  "page": 1,
  "pageSize": 9,
  "totalItems": 0,
  "totalPages": 0
}
```

Страница за пределами выдачи тоже возвращает `200` с пустым `items`, запрошенным `page` и актуальными `totalItems`/`totalPages`.

Отрицательные или дробные цены, `minPrice > maxPrice`, неизвестные непустые типы/цвета, неподдерживаемые `sort`/`direction`, нецелый `page` или `page < 1` дают `400`, `VALIDATION_ERROR`. Необязательные числовые параметры frontend при пустом поле не отправляет, а не передаёт пустой строкой.

Пример HTTP `400`:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Проверьте параметры каталога",
  "fieldErrors": {
    "maxPrice": "Максимальная цена не должна быть меньше минимальной"
  }
}
```

### GET /api/goods/{id}

Нужна сессия. Например: `GET /api/goods/1`. Тела нет. Успех — HTTP `200`, один полный объект `Product` из раздела 2, без дополнительной обёртки.

Неположительный или нецелый ID — `400`, `VALIDATION_ERROR`. Положительный ID отсутствующего товара — HTTP `404`:

```json
{
  "code": "PRODUCT_NOT_FOUND",
  "message": "Товар не найден",
  "fieldErrors": {}
}
```

Для модального окна можно использовать уже полученный полный товар из каталога. Отдельная ручка нужна для загрузки по известному ID.

## 5. Расчёт корзины

### POST /api/cart/calculate

Нужна сессия. Проверяет состав и возвращает данные для отображения. Корзина на сервере не сохраняется.

```http
POST /api/cart/calculate
Content-Type: application/json
```

```json
{
  "items": [
    { "productId": 1, "quantity": 2 }
  ]
}
```

`items` — обязательный массив `CartItemInput`. Успех — HTTP `200`:

```json
{
  "items": [
    {
      "product": {
        "id": 1,
        "name": "Внешний аккумулятор 10000mAh, белый",
        "price": 2990,
        "imageUrl": "/images/goods/image_1.png",
        "type": "Внешние аккумуляторы",
        "color": "Белый",
        "rating": 4.8,
        "isNew": true,
        "isHit": false,
        "description": "Компактный внешний аккумулятор для зарядки гаджетов.",
        "characteristics": [
          { "name": "Ёмкость", "value": "10000 мА·ч" }
        ]
      },
      "quantity": 2,
      "totalPrice": 5980
    }
  ],
  "totalQuantity": 2,
  "totalPrice": 5980
}
```

`product` — полный `Product`; `quantity` — количество единиц позиции; её `totalPrice` — цена одной единицы × количество. Корневые итоги — сумма единиц и сумма стоимости всех позиций. Порядок позиций соответствует запросу.

Для `{ "items": [] }` возвращается HTTP `200`:

```json
{
  "items": [],
  "totalQuantity": 0,
  "totalPrice": 0
}
```

Правила ошибок:

- Отсутствующий/null `items`, неправильные типы полей, неположительный `productId`, нецелое или неположительное количество, повтор одного `productId` — `400`, `VALIDATION_ERROR`.
- Неизвестный положительный ID — `400`, `PRODUCT_NOT_FOUND`.
- При любой неправильной позиции весь запрос отклоняется: частичный результат не возвращается.

Пример ошибки количества — HTTP `400`:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Проверьте состав корзины",
  "fieldErrors": {
    "items[0].quantity": "Количество должно быть положительным целым числом"
  }
}
```

Пример неизвестного товара — HTTP `400`:

```json
{
  "code": "PRODUCT_NOT_FOUND",
  "message": "Один из товаров не найден",
  "fieldErrors": {
    "items[0].productId": "Товар не найден"
  }
}
```

## 6. Заказы

### POST /api/orders

Нужна сессия. Проверяет форму и состав, повторно рассчитывает стоимость по серверным ценам и сохраняет заказ.

```http
POST /api/orders
Content-Type: application/json
```

Пример самовывоза:

```json
{
  "items": [
    { "productId": 1, "quantity": 2 }
  ],
  "phone": "+79991234567",
  "email": null,
  "deliveryMethod": "pickup",
  "address": null,
  "paymentMethod": "card",
  "packaging": false
}
```

Пример доставки:

```json
{
  "items": [
    { "productId": 1, "quantity": 2 }
  ],
  "phone": "+79991234567",
  "email": "student@example.com",
  "deliveryMethod": "delivery",
  "address": "Санкт-Петербург, ул. Барочная, д. 7, кв. 10",
  "paymentMethod": "cash",
  "packaging": true
}
```

| Поле | Обязательное | Правило |
| --- | --- | --- |
| `items` | Да | Непустой массив; правила состава как у расчёта корзины |
| `phone` | Да | Строка, непустая после удаления пробелов по краям; строгой проверки формата телефона нет |
| `email` | Нет | Отсутствие, `null` или пустая после trim строка означают отсутствие почты; непустое значение должно иметь корректный формат email |
| `deliveryMethod` | Да | `pickup` — самовывоз, `delivery` — доставка |
| `address` | Для доставки | Для `delivery` — непустая после trim строка; для `pickup` игнорируется и сохраняется как отсутствующий |
| `paymentMethod` | Да | `card` — по карте, `cash` — наличными |
| `packaging` | Нет | boolean; при отсутствии `false`, явный `null` — ошибка |

При отправке строковых полей `phone`, `email`, `address` сервер удаляет пробелы по краям. Регистрация, реальная онлайн-оплата, проверка остатков и списание товаров не реализуются. Доставка и упаковка бесплатны, поэтому итог заказа — сумма стоимости товаров.

Успех — HTTP `201`, объект `OrderSummary`:

```json
{
  "number": 1,
  "createdAt": "2026-10-24T18:30:00Z",
  "totalQuantity": 2,
  "totalPrice": 5980
}
```

- Пользователь определяется по сессии; `userId` в запрос не передаётся.
- Номер, дата, цены и итоги определяются сервером. Результат предыдущего расчёта корзины не заменяет повторную проверку при оформлении.
- В файле заказа сохраняются пользователь, форма, состав и снимки названий/цен на момент покупки. В HTTP-ответе возвращается только краткая информация выше.
- Номер заказа — последовательный, начиная с 1; нумерация продолжается после перезапуска.
- Сервер возвращает `201` только после успешной записи. Конкурентные создания не должны затирать заказы друг друга.
- Пустая корзина или неправильная форма — `400`, `VALIDATION_ERROR`. Неизвестный товар — `400`, `PRODUCT_NOT_FOUND`. Частично заказ не создаётся.
- Нет сессии — `401`, `UNAUTHORIZED`; ошибка сохранения — `500`, `INTERNAL_ERROR`.

Пример HTTP `400` для доставки:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Проверьте заполненные поля",
  "fieldErrors": {
    "phone": "Заполните обязательное поле",
    "address": "Укажите адрес доставки",
    "paymentMethod": "Выберите способ оплаты"
  }
}
```

Frontend очищает корзину только после полученного `201`, обновляет шапку и показывает номер заказа. При ошибке состав и форма сохраняются. Пока запрос выполняется, кнопку оформления блокируем от повторного нажатия.

Автоматический повтор `POST /api/orders` после сетевого сбоя не выполняется: запрос создаёт новый заказ, идемпотентность в этой версии не предусмотрена. Если ответ потерян, frontend сохраняет корзину, показывает неопределённый результат и предлагает проверить историю перед повторным оформлением.

### GET /api/orders

Нужна сессия. Параметров и тела нет. Возвращает только заказы текущего пользователя, без пагинации, новые первыми; при одинаковой дате — номер по убыванию.

Успех — HTTP `200`, массив `OrderSummary`:

```json
[
  {
    "number": 2,
    "createdAt": "2026-10-24T19:00:00Z",
    "totalQuantity": 1,
    "totalPrice": 2990
  },
  {
    "number": 1,
    "createdAt": "2026-10-24T18:30:00Z",
    "totalQuantity": 2,
    "totalPrice": 5980
  }
]
```

Пустая история — HTTP `200` с `[]`. Нет сессии — `401`, `UNAUTHORIZED`.

Строки истории не кликабельные; отдельной ручки подробностей заказа нет. Изменение цен или названий в каталоге не меняет сохранённые заказы и их итоги. История сохраняется после выхода и перезапуска сервера.

## 7. Подключение frontend и разделение ответственности

### Базовый запрос

```ts
const API_BASE = "http://localhost:8080";

const response = await fetch(`${API_BASE}/api/cart/calculate`, {
  method: "POST",
  credentials: "include",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ items: [{ productId: 1, quantity: 2 }] }),
});

// fetch не выбрасывает исключение для HTTP 400/401/404/500.
const body = response.status === 204 ? null : await response.json();
if (!response.ok) {
  // body содержит code, message и fieldErrors.
  // Обработать ошибку, не использовать её как успешные данные.
} else {
  // Использовать body как успешный ответ соответствующей ручки.
}
```

### Формат localStorage

Один общий ключ `gadgetHub.cart`; значение — JSON-строка с массивом:

```json
[
  { "productId": 1, "quantity": 2 },
  { "productId": 13, "quantity": 1 }
]
```

Отсутствующий ключ означает пустую корзину. Названия, цены, рассчитанные суммы, флаги выбора строк и данные формы заказа в этот массив не включаются. При отправке массив оборачивается в `{ "items": [...] }`.

### Общая корзина и счётчик шапки

На frontend общий модуль — `frontend/src/state/cart.ts`, экспорт `cart`. Шапка уже подключена к нему. В компонентах второго человека использовать `cart.state.items` для чтения состава, `await cart.setItems(nextItems)` для сохранения нового состава и обновления счётчика, `await cart.clear()` после успешного оформления заказа. Метод `clear()` не вызывает оформление заказа. `cart.restore()` перечитывает localStorage и запрашивает расчёт. Не создавать отдельное состояние корзины и не писать в localStorage напрямую: в текущей вкладке такие записи не уведомляют Vue. Изменения из других вкладок шапка получает через событие `storage`.

Счётчик показывает серверный `totalQuantity`, то есть число единиц всех товаров, а не число разных позиций. При нуле значок скрыт; во время расчёта показывает `…`, при ошибке — `!` и сообщение с повтором проверки. Выход очищает только реактивное состояние модуля (`cart.reset()`), сохраняя localStorage; при следующем входе корзина восстанавливается. Сам интерфейс корзины, изменение позиций и оформление остаются частью второго человека.

- Использовать единое реактивное состояние корзины для карточек, модальных окон, страницы корзины и шапки. Прямые независимые записи в localStorage из разных компонентов не делать.
- Добавление увеличивает количество существующей позиции либо создаёт новую. При уменьшении до нуля позиция удаляется из массива.
- После изменения сохранять состав в localStorage и запрашивать `/api/cart/calculate`. Вызов расчёта не создаёт заказ.
- Из ответа брать данные товаров, суммы и `totalQuantity` для счётчика шапки. Frontend не вычисляет стоимость самостоятельно.
- Не позволять устаревшему ответу расчёта перезаписать более новый: применять только ответ последнего актуального состава корзины.
- При ошибке расчёта сохранённый состав не очищать; показывать ошибку. Пока актуальный расчёт не получен, старые суммы и счётчик не выдавать за актуальные.
- Чекбоксы корзины относятся к выборочному удалению. На оформление передаётся весь текущий состав корзины. После подтверждённого удаления выбранных строк пересчитывается оставшийся состав.
- После успешного оформления удалить ключ `gadgetHub.cart`, очистить состояние корзины и установить счётчик в 0.

### Сценарии подключения

1. При запуске запросить `/api/auth/me`. Для гостя оставить доступными главную и логин. Для авторизованного пользователя восстановить корзину из localStorage и запросить её расчёт.
2. На главной получать `/api/showcase` независимо от авторизации.
3. При успешном входе сохранить пользователя в общем состоянии, восстановить расчёт корзины и перейти на главную.
4. При открытии каталога получить `/api/goods/filters` и первую страницу `/api/goods`. Параметры отправлять в согласованном формате.
5. Открывая модальное окно, использовать полный товар из каталога либо загрузить его по ID. Количество в карточках брать из общего состава корзины.
6. На странице корзины показывать серверный расчёт. До отправки заказа проверять обязательные поля, как требует курсовая; сервер повторяет валидацию.
7. На вкладке истории запрашивать `/api/orders`, в том числе после нового заказа, чтобы не показывать устаревший список.
8. При выходе завершить сессию и перейти на главную, сохранив localStorage.
9. `401 UNAUTHORIZED` на защищённой ручке сбрасывает состояние пользователя и переводит на логин. `401 INVALID_CREDENTIALS` показывает ошибку формы входа. Сетевой сбой или `500` не трактуется как выход из системы.

### Ответственность участников

**Человек 1:** весь backend по этому контракту; конфигурация сессии и CORS; общий клиент API; состояние авторизации и защита маршрутов; страница логина; шапка. Вместе со вторым человеком подключает шапку к общему состоянию корзины.

**Человек 2:** главная, каталог, модальные окна товаров, footer, общее состояние корзины и его связь с localStorage, страница корзины, форма заказа, история; подключение этих компонентов к API. Бизнес-расчёты выполняет сервер.

## 8. Контрольные сценарии

- Гость получает главную, но защищённые ручки возвращают `401`.
- Неправильный вход возвращает согласованную ошибку; правильный вход устанавливает сессию, `me` возвращает пользователя.
- После обновления страницы сессия восстанавливается; после выхода защищённые ручки снова недоступны.
- Цвета внутри одной группы объединяются через «или», тип/цвет/цена — через «и»; пустой выбор не ограничивает каталог.
- Работают сортировка, стабильный порядок, страницы по 9 товаров и пустая выдача.
- Корзина восстанавливается из localStorage; суммы и счётчик соответствуют серверному расчёту; количество 0 не отправляется.
- Неизвестный товар, повтор позиции и неправильное количество отклоняют расчёт или заказ целиком.
- Самовывоз оформляется без адреса; доставка без адреса отклоняется; email необязателен.
- Цена и итоги заказа берутся из каталога сервера; пользователь определяется по сессии.
- После `201` корзина очищается, заказ появляется в истории. При ошибке сохранения успех не показывается и корзина остаётся.
- Заказы и нумерация сохраняются после перезапуска backend; изменение каталога не меняет старые итоги.
